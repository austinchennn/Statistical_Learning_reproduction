# 共用一套保存下来的 fold 划分（Shared, Persisted Fold Assignment）

前置：[01_K折交叉验证.md](01_K折交叉验证.md)、[03_OOF预测文件.md](03_OOF预测文件.md)

## 1. 定义与公式

事先生成一次**样本到折号的映射**，保存成文件，所有基模型（以及 meta 的交叉验证）都读取它，而不是各自随机切分：

$$k: \{1,\dots,n\} \to \{1,\dots,K\},\qquad D_k = \{\, i : k(i) = k \,\}$$

"共用"的意思是：对任意两个基模型 $a, b$，它们的折外预测都满足

$$z_a^{(i)} = h_a^{(-k(i))}(\mathbf{x}^{(i)}),\quad z_b^{(i)} = h_b^{(-k(i))}(\mathbf{x}^{(i)})$$

两者用的是**同一个** $k(i)$，也就是同一行 Z 的所有列，都是由"在**同一批**数据 $D \setminus D_{k(i)}$ 上训练"的模型产生的。

代码对应：[stacking.py](../stacking.py) 中的 `make_folds()` 只调用一次，结果传给所有基模型。

## 2. 形象的例子

几位老师各自出题评估同一批学生。如果每位老师随手把学生分成"练习组/考试组"，那么：
- 张老师考的是小明，李老师考的是小红，两位老师的分数没法直接比较谁出题更好。
- 学生的"成绩单"上每一栏也来自不同的考试条件。

统一做法是教务处**一次性排好分组表贴在墙上**，所有老师都照表执行。之后换老师、加老师，也照同一张表。

## 3. 带数据的例子

保存下来的划分文件 `folds/folds_2026-09-30_seed42.parquet`：

| sample_id | fold_id |
|---|---|
| 1 | 1 |
| 2 | 1 |
| 3 | 2 |
| 4 | 2 |
| 5 | 3 |
| 6 | 3 |

**共用划分时**（前几篇的数据）：均值模型 A 的各折 MSE 是 10, 4, 13，1-NN 模型 B 的各折 MSE 是 1, 2.5, 4。每一折都是在**完全相同的训练/验证样本**上比较，所以可以逐折说"B 在每一折都比 A 好"，比较是配对的，结论可信。

**不共用时**：假设 B 改用另一套切分 {1,4}, {2,5}, {3,6}：

- 第 1 折留出 $x=1,4$，训练 $x \in \{2,3,5,6\}$：$x=1$ → 最近邻 $x=2$ → 5；$x=4$ → 最近邻 $x=3$ → 4
- 第 2 折留出 $x=2,5$，训练 $x \in \{1,3,4,6\}$：$x=2$ → 最近邻 $x=1$ → 3；$x=5$ → 最近邻 $x=4$ → 8
- 第 3 折留出 $x=3,6$，训练 $x \in \{1,2,4,5\}$：$x=3$ → 最近邻 $x=2$ → 5；$x=6$ → 最近邻 $x=5$ → 6

B 的 OOF 变成 $[5,3,5,4,8,6]$，MSE = (4+4+1+16+4+16)/6 = **7.5**，而原来是 **2.5**。
同一个模型、同一份数据，只是切法不同，分数就差了 3 倍（小数据时尤其明显）。此时拿 B 的 7.5 和 A 的 9 比较，你根本分不清差异来自模型还是来自切分。meta 看到的 Z 也跟着变了。

## 4. 为什么用它、来源、解决的问题

- **来源**：Kaggle 团队融合时的惯例（"everyone uses the same folds"），工业界 ML 平台把它固化成 "fold assignment 作为数据集的一部分"来版本管理。
- **解决的问题**：
  1. **模型之间可比**：所有模型的 CV 分数是在相同条件下测的，可以做配对比较，选模型、删模型才有依据。
  2. **Z 的每一行语义一致**：同一样本的所有元特征都来自"没见过同一批数据"的模型。
  3. **meta 的交叉验证更干净**：meta 也用同一套 fold 做 CV 时，折边界对齐，更容易推理哪些信息被谁看到过。（严格来说，fold $j$ 的 OOF 模型见过 fold $k$ 的数据，因此 meta 的 CV 仍有轻微乐观偏差，这在实践中通常被接受；需要严格估计时用独立 hold-out 集。）
  4. **可复现**：随机种子、库版本变化都不会改变划分。
  5. **可以增量加模型**：半年后新加一个基模型，照同一张表跑，就能直接和旧 OOF 文件拼在一起。

## 5. 优缺点

**优点**
- 可比、可复现、可增量协作。
- 把"怎么切"这个容易出错的决定集中在一处，分组/时间/分层约束只需写对一次。

**缺点**
- 所有结论都绑定在这一次切分上，如果这次切分恰好不走运，所有模型会一起被影响（可用多个种子重复做来缓解，但成本翻倍）。
- 训练数据更新（新增样本）后，要么重新生成划分并重跑所有基模型，要么设计好新样本的折号分配规则。

## 6. 工程师必须会 / 必须注意

1. **划分文件以 `sample_id → fold_id` 保存**，不要只保存随机种子。种子在不同库版本、不同行顺序下可能产生不同切分。
2. **切分约束要一次写对**：分类用分层，同一用户/病人用分组，时间序列按时间（见 [01_K折交叉验证.md](01_K折交叉验证.md) 第 6 节）。所有模型继承这个约束。
3. **给划分起版本名**（如 `folds_2026-09-30_seed42`），写进每个 OOF 文件的元信息里；meta 任务启动时**断言所有输入文件的划分版本相同**，不同就直接报错。
4. **任何折内操作都用同一张表**：目标编码、特征选择、超参搜索如果有自己的内层 CV，也要保证不跨越外层 fold 边界，否则泄漏。
5. **数据集变了就换划分版本**，同时视所有旧 OOF 文件为作废，不要把新旧划分产出的文件混在一起。
